# HOSTLY_EDITOR_HUMANIZATION_ROADMAP

> Roadmap estrategico para transformar el Editor V2 de Hostly en una experiencia comercial, humana y centrada en hosteleria.

**Estado:** documento maestro de producto  
**Ambito:** evolucion de experiencia del Editor V2  
**Autoridad:** complementa `HOSTLY_EDITOR_EXPERIENCE_GUIDELINES.md`  
**Horizonte:** guia para los proximos diez anos de evolucion del Editor  
**Ultima revision:** 2026-07-05  

---

## 1. Proposito

Este documento define la estrategia de Humanizacion del Editor V2 de Hostly.

No cuestiona la arquitectura existente. No propone rehacer los fundamentos del producto. No describe implementacion. No es un backlog. No es una lista de tareas.

Su objetivo es establecer una hoja de ruta de producto para transformar progresivamente la percepcion del Editor V2:

De una herramienta potente que todavia puede sentirse tecnica.

A una experiencia comercial de primer nivel donde un responsable de hosteleria siente:

**Estoy construyendo mi restaurante.**

La Humanizacion del Editor es el puente entre la solidez interna ya conseguida y la experiencia que Hostly quiere vender durante los proximos anos.

---

## 2. Relacion Con La Constitucion Del Editor

El documento `HOSTLY_EDITOR_EXPERIENCE_GUIDELINES.md` define la vision.

Este documento define el camino para llegar a esa vision.

La Constitucion responde:

- Como debe sentirse el Editor.
- Que modelo mental debe proteger.
- Que lenguaje debe usar.
- Que principios no deben romperse.

Este roadmap responde:

- Que debe madurar primero.
- Que percepciones deben cambiar.
- Que riesgos deben evitarse.
- Como saber si la evolucion avanza en la direccion correcta.

La Constitucion es el destino.  
La Humanizacion es la estrategia de transicion.

## 3. Filosofia De La Humanizacion

### 3.1 Por que hablamos de Humanizacion

Hablamos de Humanizacion porque el problema principal del Editor V2 ya no es la capacidad del producto.

El problema es la distancia entre la estructura interna y la forma en que piensa una persona real que gestiona un restaurante.

Hostly puede tener una base interna profunda, precisa y escalable. Pero el usuario no compra esa profundidad. El usuario compra claridad, control y rapidez.

Humanizar el Editor significa traducir la potencia del producto a una experiencia que se sienta natural para hosteleria.

Significa que el usuario no vea sistemas.  
Vea su sala.

No vea fases.  
Vea el proceso de montar su restaurante.

No vea herramientas.  
Vea objetos y decisiones que reconoce.

No vea complejidad.  
Vea control.

### 3.2 Que significa realmente

Humanizar el Editor significa:

- Cambiar la percepcion sin romper la base.
- Hablar el idioma del restaurante.
- Ordenar la experiencia segun el pensamiento del encargado.
- Hacer que la operacion aparezca antes que la decoracion.
- Reducir carga mental.
- Hacer que lo esencial este siempre cerca.
- Convertir la complejidad interna en decisiones simples.
- Hacer que el primer plano util llegue antes.
- Conseguir que el usuario sienta que el Editor entiende su negocio.

La Humanizacion no es una capa estetica. Es una estrategia de producto.

### 3.3 Que NO significa

Humanizar no significa infantilizar.

Hostly no debe parecer una herramienta simple para principiantes. Debe parecer una herramienta profesional que no obliga a sufrir.

Humanizar no significa ocultarlo todo.

La complejidad puede aparecer cuando aporta valor, pero no debe ser el punto de partida.

Humanizar no significa reducir ambicion.

El Editor puede representar restaurantes, hoteles, terrazas, rooftops, resorts y beach clubs. La cuestion es que esa amplitud no debe convertirse en ruido.

Humanizar no significa convertir el Editor en una demo bonita.

La experiencia debe seguir siendo operativa, robusta y comercial.

Humanizar no significa renunciar a la precision.

Significa que la precision debe servir a la operacion, no dominar el modelo mental.

## 4. Principios De La Evolucion

Estos principios gobiernan toda la Humanizacion del Editor V2.

### 4.1 La arquitectura se mantiene

La base actual queda aprobada.

La Humanizacion no existe para rehacer el producto. Existe para hacer que el usuario no tenga que pensar en como esta hecho.

### 4.2 Cambia la percepcion

La pregunta no es solo que puede hacer el Editor.

La pregunta es que cree el usuario que esta haciendo.

Si cree que esta configurando una herramienta, la experiencia falla.  
Si cree que esta construyendo su restaurante, la experiencia avanza.

### 4.3 Cambia el lenguaje

El lenguaje visible debe pertenecer a la hosteleria.

El usuario debe ver palabras como:

- restaurante;
- sala;
- terraza;
- mesas;
- barra;
- servicio;
- accesos;
- ambiente;
- exterior.

No debe ver el idioma interno del producto como protagonista.

### 4.4 Cambia el flujo

El flujo debe seguir la forma natural de pensar de un encargado:

1. Que espacios tengo.
2. Donde estan los limites.
3. Donde se sientan los clientes.
4. Donde trabaja el equipo.
5. Como reconozco mi local.
6. Si el plano sirve para operar.

El flujo no debe pedir al usuario que aprenda el orden interno del Editor.

### 4.5 Nunca aumentar complejidad

Cada mejora debe reducir carga mental o aportar claridad evidente.

Si una decision hace que el producto parezca mas potente pero mas dificil, debe cuestionarse.

### 4.6 Nunca ensenar el sistema interno

El usuario no debe tener que conocer fases, sistemas, capas o familias internas para avanzar.

La complejidad puede existir por dentro. No debe convertirse en el idioma de la experiencia.

### 4.7 La operacion manda

Mesas, estados, servicio, barras, recepcion, recogida y capacidad deben dominar la experiencia.

El espacio da contexto.  
El ambiente da reconocimiento.  
La operacion da sentido.

### 4.8 La biblioteca debe ser curada

La Humanizacion no consiste en anadir mas objetos.

Consiste en que los objetos esenciales sean mas claros, mas faciles de encontrar y mas utiles para crear un restaurante real.

### 4.9 Lo tactil es una condicion de producto

El Editor debe sentirse natural en tablet y portatil tactil.

No basta con que funcione. Debe sentirse comodo, seguro y directo.

### 4.10 La belleza esta subordinada a la comprension

El Editor debe verse profesional y atractivo, pero nunca debe sacrificar legibilidad operativa.

Un plano bello que dificulta leer mesas no es un buen plano de Hostly.

### 4.11 La consolidacion precede a la expansion

Antes de ampliar capacidades, el Editor debe consolidar su experiencia base.

Un producto dificil con muchas funciones no es mas comercial. Es mas dificil de vender, explicar y adoptar.

## 5. Roadmap Estrategico Por Etapas

Este roadmap no describe implementacion. Describe una secuencia de maduracion de producto.

Cada etapa existe para acercar el Editor a una experiencia donde el usuario piensa menos en el software y mas en su restaurante.

---

## Etapa 1 - Traduccion Del Modelo Mental

### Objetivo

Sustituir la percepcion de fases tecnicas por una percepcion centrada en el restaurante.

El usuario debe dejar de sentir que avanza por conceptos internos y empezar a sentir que esta dando forma a su negocio.

### Impacto esperado

- Menos intimidacion inicial.
- Mayor comprension del proposito del Editor.
- Menos necesidad de explicar como funciona.
- Primer contacto mas comercial.
- Mayor sensacion de producto pensado para hosteleria real.

### Que cambia

- Cambia el idioma principal de la experiencia.
- Cambia el orden mental con el que se presentan las decisiones.
- Cambia la forma de agrupar acciones visibles.
- Cambia el peso de las palabras internas.
- Cambia la sensacion de estar "usando un editor" por "construyendo mi restaurante".

### Que NO cambia

- No cambia la base aprobada del producto.
- No cambia la capacidad de representar espacios complejos.
- No cambia la profundidad futura del Editor.
- No cambia la ambicion de Hostly.

### Criterio para considerarla terminada

Esta etapa se considera terminada cuando un usuario nuevo puede describir lo que esta haciendo con palabras de restaurante, no con palabras del Editor.

La prueba es simple:

Si el usuario dice "estoy creando mi sala y colocando mis mesas", la etapa avanza.

Si dice "estoy en una fase y tengo que elegir una herramienta", la etapa no esta completada.

---

## Etapa 2 - Primer Plano Util

### Objetivo

Reducir el tiempo hasta que el usuario consigue un plano reconocible y operativo.

El primer exito no debe ser un plano perfecto. Debe ser un plano suficientemente claro para que el usuario piense:

**Esto ya se parece a mi restaurante.**

### Impacto esperado

- Mayor confianza temprana.
- Menos abandono.
- Menos sensacion de complejidad.
- Mejor demostracion comercial.
- Mayor percepcion de rapidez.

### Que cambia

- Cambia la prioridad de la experiencia inicial.
- Cambia la forma de guiar al usuario hacia lo esencial.
- Cambia el peso de configuraciones secundarias.
- Cambia la importancia relativa de mesas, sala, barra y accesos al principio.

### Que NO cambia

- No desaparece la posibilidad de ajustar detalles.
- No se limita el tipo de establecimiento que puede representarse.
- No se renuncia a precision cuando sea necesaria.
- No se reduce la capacidad futura del Editor.

### Criterio para considerarla terminada

Esta etapa se considera terminada cuando un encargado puede construir una sala basica con mesas, barra y accesos sin detenerse a entender categorias internas.

El usuario debe llegar rapido a una version util, aunque despues pueda perfeccionarla.

---

## Etapa 3 - Operacion Como Centro De Gravedad

### Objetivo

Hacer que toda la experiencia se ordene alrededor de la operacion real del restaurante.

La pregunta principal no debe ser "que puedo dibujar", sino "como se trabaja en este espacio".

### Impacto esperado

- Mesas mas importantes y reconocibles.
- Mayor claridad durante el servicio.
- Menos competencia visual entre ambiente y operacion.
- Mas confianza del usuario en que el plano sirve para trabajar.
- Mejor conexion entre editor y producto Hostly completo.

### Que cambia

- Cambia el peso visual y conceptual de las mesas.
- Cambia la prioridad de barras, recepcion, estaciones y recogida.
- Cambia la relacion entre decoracion y servicio.
- Cambia el criterio para evaluar materiales, ambiente y elementos visuales.

### Que NO cambia

- No desaparece el ambiente.
- No desaparece la riqueza visual.
- No se convierte el Editor en un TPV antiguo.
- No se renuncia a representar locales premium.

### Criterio para considerarla terminada

Esta etapa se considera terminada cuando, ante cualquier plano, la lectura de mesas y servicio es inmediata.

Si el usuario tiene que mirar dos veces para encontrar las mesas, la etapa no esta completada.

---

## Etapa 4 - Biblioteca Profesional Y Curada

### Objetivo

Convertir la biblioteca en un repertorio claro, comercial y hostelero.

La biblioteca debe dejar de sentirse como un panel de herramientas y empezar a sentirse como una seleccion profesional de elementos para construir un restaurante.

### Impacto esperado

- Menos busqueda.
- Mayor confianza.
- Mejor sensacion tactil.
- Mayor claridad entre objetos esenciales y secundarios.
- Menos ruido por elementos no necesarios.

### Que cambia

- Cambia la forma en que el usuario descubre objetos.
- Cambia la prioridad de los elementos esenciales.
- Cambia la sensacion de catalogo tecnico por repertorio curado.
- Cambia la tolerancia a elementos ambiguos, redundantes o demasiado especificos.

### Que NO cambia

- No se amplia la biblioteca por cantidad.
- No se convierte en una galeria decorativa.
- No se pierden las familias internas ya aprobadas.
- No se cambia la ambicion de cubrir multiples tipologias de hosteleria.

### Criterio para considerarla terminada

Esta etapa se considera terminada cuando un usuario encuentra en pocos segundos los elementos basicos para montar su negocio:

- mesas;
- barra;
- accesos;
- limites;
- terraza o sala;
- servicio;
- ambiente esencial.

Si necesita explorar demasiado para encontrar lo comun, la biblioteca no esta humanizada.

---

## Etapa 5 - Claridad Tactil

### Objetivo

Hacer que el Editor se sienta comodo en manos reales.

Hostly debe funcionar para usuarios que no trabajan todo el dia con precision de escritorio. Un encargado puede usar tablet, portatil tactil o un dispositivo en entorno operativo.

### Impacto esperado

- Menos errores de seleccion.
- Mayor confianza al mover objetos.
- Menos frustracion.
- Mayor sensacion de control.
- Mejor adopcion en contextos reales.

### Que cambia

- Cambia la exigencia de precision.
- Cambia la sensacion de tocar, arrastrar, seleccionar y ajustar.
- Cambia el peso de acciones contextuales.
- Cambia la tolerancia a elementos pequenos, densos o escondidos.

### Que NO cambia

- No se simplifica el producto hasta hacerlo basico.
- No se elimina la experiencia de escritorio.
- No se sacrifica precision profesional.
- No se convierte en una app exclusivamente tactil.

### Criterio para considerarla terminada

Esta etapa se considera terminada cuando un usuario puede crear y ajustar un plano en tablet sin sentir que necesita punteria fina, paciencia extra o conocimiento avanzado.

La experiencia tactil debe sentirse natural, no simplemente posible.

---

## Etapa 6 - Coherencia Comercial

### Objetivo

Conseguir que todo el Editor parezca disenado por una unica vision de producto.

La experiencia debe dejar de mostrar capas historicas, nombres de sistemas o diferencias de madurez entre partes.

### Impacto esperado

- Mayor percepcion de calidad.
- Mayor confianza comercial.
- Mejor defensa del producto en demos.
- Menos sensacion de prototipo.
- Mayor consistencia para futuras evoluciones.

### Que cambia

- Cambia la coherencia entre paneles, biblioteca, canvas, lenguaje y estados.
- Cambia la relacion entre experiencia visual y operativa.
- Cambia la forma de evaluar nuevas decisiones.
- Cambia la exigencia de calidad antes de incorporar nuevas capacidades visibles.

### Que NO cambia

- No se redisenan los fundamentos aprobados.
- No se reescribe el producto.
- No se anaden nuevas promesas comerciales.
- No se convierte el Editor en una pieza de marketing.

### Criterio para considerarla terminada

Esta etapa se considera terminada cuando el Editor puede mostrarse a un cliente potencial sin explicaciones defensivas.

La experiencia debe hablar por si misma:

**Este producto entiende mi restaurante.**

---

## Etapa 7 - Madurez De Producto

### Objetivo

Establecer un criterio permanente para que el Editor siga evolucionando durante anos sin perder claridad.

La Humanizacion no es un proyecto puntual. Es una forma de gobernar el crecimiento.

### Impacto esperado

- Crecimiento mas disciplinado.
- Menos acumulacion de complejidad.
- Mayor consistencia entre nuevas capacidades.
- Mejor alineacion entre producto, diseno y desarrollo futuro.
- Mayor capacidad de mantener una experiencia premium a largo plazo.

### Que cambia

- Cambia la forma de aceptar nuevas ideas.
- Cambia la forma de priorizar mejoras.
- Cambia la forma de medir calidad.
- Cambia la relacion entre capacidad y experiencia.

### Que NO cambia

- No se bloquea la innovacion.
- No se impide que el Editor crezca.
- No se limita Hostly a casos simples.
- No se renuncia a representar establecimientos complejos.

### Criterio para considerarla terminada

Esta etapa nunca termina del todo.

Se considera madura cuando cada decision futura del Editor se evalua primero por su impacto en la experiencia del usuario, no por su atractivo interno.

## 6. Riesgos Estrategicos

### 6.1 Convertir el Editor en un CAD

El riesgo es priorizar precision, controles y conceptos tecnicos por encima de comprension operativa.

Hostly debe poder representar espacios complejos sin exigir mentalidad de arquitecto.

### 6.2 Convertir el Editor en Paint

El riesgo opuesto es dar demasiada libertad sin estructura.

Un lienzo libre puede parecer flexible, pero genera inconsistencia y carga mental.

Hostly debe guiar sin encerrar.

### 6.3 Convertir el Editor en un videojuego

El riesgo es buscar realismo, efecto visual o espectacularidad por encima de utilidad.

Un restaurante debe reconocerse, no renderizarse como una escena.

### 6.4 Anadir funciones antes de consolidar experiencia

Mas funciones pueden empeorar el producto si la base mental no esta clara.

La consolidacion de experiencia debe preceder a la expansion visible.

### 6.5 Ensenar demasiada arquitectura

El usuario no debe sentir que interactua con sistemas.

Cada vez que aparece una palabra interna, una fase o una categoria tecnica, el Editor pierde humanidad.

### 6.6 Crecer por cantidad

Una biblioteca mas grande no significa un Editor mejor.

El crecimiento debe ser curado, no acumulativo.

### 6.7 Confundir profesionalidad con complejidad

Un producto profesional no es el que muestra mas opciones.

Es el que permite tomar mejores decisiones con menos esfuerzo.

### 6.8 Confundir sencillez con falta de potencia

Hostly no debe parecer basico.

Debe parecer claro.

La sencillez del Editor debe ser el resultado de una gran sofisticacion escondida.

### 6.9 Hacer que la decoracion gane a la operacion

La riqueza visual es importante, pero las mesas, el servicio y la lectura del plano mandan.

Cuando ambiente y operacion compiten, gana siempre la operacion.

### 6.10 Resolver friccion con explicaciones

Si el usuario necesita leer mucho para entender el Editor, la experiencia no esta resuelta.

La ayuda puede acompanar. No debe compensar una experiencia confusa.

### 6.11 Disenar para demos internas

El Editor no debe optimizarse para impresionar al equipo.

Debe optimizarse para que un cliente real lo entienda, lo use y confie en el.

### 6.12 Perder el foco hostelero

Hostly no compite con herramientas genericas de diseno.

Su ventaja esta en entender hosteleria mejor que nadie.

## 7. Criterios Oficiales De Decision

Toda decision futura del Editor debe pasar por este filtro.

### 7.1 Filtro de comprension

- Esto ayuda a un encargado a entender antes el Editor?
- Esto se entiende sin explicacion?
- Esto reduce dudas?
- Esto hace que el usuario piense en su restaurante?
- Esto elimina lenguaje interno?

### 7.2 Filtro de rapidez

- Esto ayuda a crear un restaurante mas rapido?
- Esto reduce pasos antes del primer plano util?
- Esto evita busquedas innecesarias?
- Esto acerca lo esencial?
- Esto elimina decisiones prematuras?

### 7.3 Filtro de hosteleria

- Esto habla el idioma de la hosteleria?
- Esto representa una situacion real de restaurante?
- Esto ayuda a bares, cafeterias, terrazas, hoteles, rooftops, resorts o beach clubs?
- Esto seria entendido por un encargado sin formacion tecnica?
- Esto mejora la conexion entre espacio y servicio?

### 7.4 Filtro de operacion

- Esto mejora la lectura de mesas?
- Esto mejora la lectura del servicio?
- Esto ayuda a entender barras, accesos, estaciones o recogida?
- Esto evita errores durante la operacion?
- Esto hace que el plano sea mas util en un turno real?

### 7.5 Filtro de carga mental

- Esto reduce carga mental?
- Esto evita que el usuario piense en sistemas?
- Esto simplifica una decision?
- Esto agrupa mejor lo que el usuario entiende junto?
- Esto oculta complejidad hasta que sea necesaria?

### 7.6 Filtro de foco visual

- Esto respeta Operacion > Espacio > Ambiente?
- Esto hace que las mesas destaquen mas?
- Esto evita que materiales o decoracion compitan?
- Esto mejora la lectura general del plano?
- Esto hace que el resultado parezca mas profesional?

### 7.7 Filtro de crecimiento

- Esto debe existir ahora?
- Esto aporta valor frecuente o solo variedad?
- Esto puede mantenerse coherente durante anos?
- Esto escala sin convertir la biblioteca en ruido?
- Esto fortalece la vision o la dispersa?

### 7.8 Filtro comercial

- Esto haria que un cliente confie mas en Hostly?
- Esto ayuda a vender el Editor sin explicaciones largas?
- Esto reduce miedo a la adopcion?
- Esto se siente como producto terminado?
- Esto diferencia a Hostly de un TPV antiguo y de un editor generico?

Si una decision no supera estos filtros, no debe entrar en la experiencia principal.

---

## 8. Que NO Debemos Hacer

Esta seccion define decisiones que pueden parecer atractivas, pero van contra la vision del Editor.

### 8.1 No convertir fases internas en navegacion principal

Aunque las fases sean utiles internamente, no deben dominar el pensamiento del usuario.

El usuario debe pensar en espacios, mesas, servicio y ambiente.

### 8.2 No ampliar la biblioteca para parecer mas completo

Mas objetos no garantizan mejor producto.

Una biblioteca excesiva aumenta carga mental y reduce velocidad.

### 8.3 No usar lenguaje tecnico para parecer profesional

La profesionalidad no viene de palabras complejas.

Viene de claridad, confianza y utilidad real.

### 8.4 No usar el onboarding como solucion principal

Si el Editor necesita demasiada explicacion, el problema no es falta de onboarding. Es falta de claridad.

### 8.5 No priorizar decoracion sobre operacion

Un plano atractivo que oculta mesas es peor que un plano simple y operativo.

### 8.6 No convertir cada caso especial en una opcion visible

El Editor debe soportar variedad sin convertir la interfaz en una lista infinita.

### 8.7 No copiar herramientas genericas

Hostly no debe parecer un editor de diseno adaptado a restaurantes.

Debe parecer una herramienta nacida desde la hosteleria.

### 8.8 No prometer futuro como si fuera presente

Las capacidades en evolucion deben tratarse con prudencia.

La confianza comercial se construye con claridad, no con promesas excesivas.

### 8.9 No esconder lo esencial

Mesas, barra, accesos y servicio deben estar cerca.

Si lo esencial queda enterrado, el Editor pierde velocidad.

### 8.10 No disenar solo para usuarios expertos

Los expertos deben poder trabajar rapido, pero el primer contacto debe ser comprensible para un usuario nuevo.

### 8.11 No hacer que lo tactil sea secundario

Tablet y portatil tactil no son casos menores.

En hosteleria, tocar, mover y ajustar debe sentirse natural.

### 8.12 No llamar simplicidad a quitar valor

Simplificar no significa empobrecer.

Significa hacer que el valor aparezca con menos esfuerzo.

### 8.13 No convertir el Editor en una vitrina visual

El Editor no existe para demostrar assets.

Existe para construir un restaurante operable.

### 8.14 No dejar que cada nueva mejora cree un nuevo idioma

El lenguaje debe mantenerse estable.

Cada nueva capacidad debe integrarse en el idioma de Hostly, no inventar uno propio.

### 8.15 No medir exito por cantidad de opciones

El exito se mide por velocidad, claridad, confianza y utilidad operativa.

---

## 9. Indicadores De Madurez

La Humanizacion del Editor avanza cuando se cumplen estas senales:

- Un usuario nuevo entiende que esta creando su restaurante sin explicacion larga.
- Las palabras visibles pertenecen a la hosteleria.
- Las mesas son lo primero que se lee.
- La biblioteca parece curada, no acumulativa.
- El plano es util antes de ser decorativo.
- El usuario no necesita entender sistemas internos.
- La experiencia tactil se siente natural.
- El primer plano util aparece pronto.
- El Editor se puede demostrar comercialmente sin justificar su complejidad.
- Cada nueva decision refuerza la vision, no la dispersa.

La Humanizacion no se mide por cuantas cosas se han cambiado.

Se mide por cuantas dudas se han eliminado.

---

## 10. Veredicto Final

La Humanizacion del Editor puede convertirse en una ventaja competitiva decisiva para Hostly.

Muchos productos de hosteleria obligan al usuario a adaptarse al software. Muchos editores visuales obligan al usuario a pensar como disenador, arquitecto o tecnico. Muchos TPV antiguos simplifican tanto el plano que pierden riqueza espacial.

Hostly puede ocupar una posicion distinta:

**un editor visual profesional que entiende como piensa y trabaja la hosteleria real.**

Esa posicion no se gana solo con tecnologia. Se gana haciendo que la tecnologia desaparezca lo suficiente para que el usuario vea su negocio.

La arquitectura interna ya permite construir un producto ambicioso.

La Humanizacion debe permitir venderlo, adoptarlo y mantenerlo durante anos.

El objetivo final no es que el usuario diga:

"Este editor tiene muchas funciones."

El objetivo es que diga:

**"Este es mi restaurante. Lo entiendo. Lo puedo usar."**

Cuando Hostly consiga eso de forma consistente, el Editor V2 dejara de ser una herramienta avanzada y se convertira en una ventaja comercial central del producto.
