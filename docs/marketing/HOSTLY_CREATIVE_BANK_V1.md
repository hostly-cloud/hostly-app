# HOSTLY — CREATIVE BANK V1

Banco previo al lanzamiento. Ninguna campaña se activa desde este documento.

## Principio creativo

No enseñar software por enseñar software. Cada pieza debe empezar con una situación que un propietario, gerente o camarero reconozca inmediatamente y terminar mostrando una mejora concreta.

## 1. Anuncios de problema -> solución

### A01 — El restaurante entero
Hook: "¿Cuántas herramientas necesita tu restaurante para terminar un servicio?"
Desarrollo: reservas, mesas, comandas, cocina, barra y cobro aparecen separadas; transición a Hostly conectado.
Cierre: "El restaurante entero, bajo control."
CTA: "Ver Hostly en acción".

### A02 — Menos clics
Hook: "En hora punta, cada clic sobra."
Visual: secuencia rápida de abrir mesa -> añadir producto -> enviar -> cobrar.
Cierre: "Menos clics. Menos esperas. Más servicio."

### A03 — Cocina no debería preguntar
Hook: "¿Mesa 12? ¿Esto era para cocina o barra?"
Visual: KDS separado por destino y estado.
Cierre: "Sala, cocina y barra leyendo la misma operación."

### A04 — Plano vivo
Hook: "Tu sala cambia cada minuto. Tu TPV debería saberlo."
Visual: plano de mesas con estados.
Cierre: "Entiende la sala de un vistazo."

### A05 — Formación
Hook: "Un TPV no debería necesitar un manual de 80 páginas."
Visual: acciones principales de Hostly.
Cierre: "Diseñado para aprender trabajando."

### A06 — Carta por foto
Hook: "¿Y si crear tu carta empezara con una foto?"
Visual: importación -> revisión -> productos.
Cierre: "IA para quitar trabajo, no control."

### A07 — Operación conectada
Hook: "El problema no es tener un TPV. Es tener cinco sistemas que no hablan entre sí."
Visual: módulos convergiendo en Hostly.
Cierre: "Una operación. Un contexto."

### A08 — Restaurante real
Hook: "Hostly no se diseñó para una oficina."
Visual: tablet, móvil, KDS, plano.
Cierre: "Software diseñado alrededor del servicio real."

## 3. Guiones verticales 20–30 s

### V01 — Hora punta
0–2s: texto: "21:37. Restaurante lleno."
2–6s: camarero necesita saber qué pasa con una mesa.
6–12s: plano Hostly -> mesa -> cuenta.
12–18s: KDS con estado de comandas.
18–23s: cobro.
23–27s: "Menos clics. Menos esperas. Más servicio."
27–30s: logo + "Ver Hostly en acción".

### V02 — Carta
0–3s: fotografía de una carta.
3–8s: "Crear 80 productos a mano..."
8–15s: importación asistida por IA.
15–22s: revisión humana.
22–27s: carta preparada.
27–30s: "IA útil. Tú mantienes el control."

### V03 — Cocina
0–3s: "¿Dónde está mi comanda?"
3–10s: KDS mostrando pendientes y preparados.
10–18s: flujo cocina/barra/sala.
18–25s: "Todo el equipo leyendo la misma operación."
25–30s: Hostly.

Un saludo,
Hostly

## 7. Reglas del banco creativo

- No usar testimonios inventados.
- No afirmar ahorros porcentuales sin datos medidos.
- No presentar funciones de roadmap como disponibles.
- Cuando una función sea futura, marcarla claramente.
- Usar capturas o mockups fieles al producto.
- No exponer datos reales de clientes/restaurantes en creatividades.
- Cada anuncio debe tener un único mensaje principal.
